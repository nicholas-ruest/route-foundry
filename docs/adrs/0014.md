# ADR-0014: Idempotency and correlation contract

## Context
Route Foundry must make a reviewable inference-routing decision without allowing optimization, UI code, or a degraded dependency to cross the policy and evidence boundary governed by **Idempotency and correlation contract**.

## Alternatives
We considered embedding the concern in the React client, leaving it implicit in the orchestrator, and owning it behind a typed Rust port. Client authority is bypassable and implicit orchestration is not independently testable.

## Decision
The owning crate named in the architecture map exposes a narrow typed API. The orchestrator calls it in the documented order, emits a correlation-bearing result, and treats error or ambiguity as a closed decision. For this decision specifically,  is part of the primary or failure journey rather than a documentation-only component.

## Tradeoffs and consequences
The boundary adds a crate and explicit conversion, but makes policy order, replay semantics, and ablations observable. It cannot be bypassed by the TypeScript client. Synthetic provider behavior is labelled and never presented as a live service result.

## Validation
Unit tests cover the local invariant; integration tests cover the caller edge;  exercises the browser path; semantic review checks implementation and traceability on the exact candidate SHA.
