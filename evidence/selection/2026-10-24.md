# Selection receipt — 2026-10-24

## Capability
Route Foundry is an audit-constrained adaptive inference control plane that selects and executes a permitted model route for each workload using verified policy, recalled outcome analogues, and split-conformal quality bounds, then persists the replayable decision in RVF.

## Distinctness
The dated ledger was checked against Provenance Firebreak, Continuity Atlas, Context Ferry, Counterfactual Shield, Canary Covenant, Causal Tapestry, Commitment Horizon, and Purpose Lattice. None performs per-request multi-provider selection or learns a safe routing set from empirical outcome calibration. This is not SLO commitment forecasting, rollout governance, purpose governance, incident reconstruction, or context transfer.

## Users and workload
Platform reliability and AI-governance teams route synthetic support, coding, and summarization requests across an on-prem model and two external providers. Each request carries data class, residency, cost, latency, and minimum-quality constraints. Operators need a visible choice, reasons, comparable candidates, failure recovery, and restart-durable audit retrieval.

## Interacting bounded contexts
1. Workload Intake validates identity and hard constraints.
2. Provider Assurance maintains candidate health, empirical quality samples, price, latency, residency, and external-processing flags.
3. Safe Routing forms a conformal feasible set and chooses within it using a contextual optimism score.
4. Policy Enforcement executes Regorus before any provider or persistence side effect.
5. Intelligence and Evidence recalls RuVector analogues and appends decisions to RVF.
6. Product Delivery exposes the Axum API, checked TypeScript client, React console, and three browser journeys.

## Composition
- Ruvnet RuVector Core 2.4.0: executed insert/search of prior routing outcomes.
- Ruvnet RVF Runtime 0.3.2: executed append, reopen, and read of durable routing/audit records.
- Microsoft Regorus 0.13.0, Apache-2.0: executed Rego route authorization boundary.
- Frontier mechanism: split-conformal lower quality bound combined with constrained upper-confidence routing; the conformal feasible set changes which providers the bandit may select.

## Success criteria and ablations
- A browser request crosses auth, policy, calibration, RuVector recall, scoring, simulated provider execution, RVF append, and renders a route with correlation id.
- Restricted data cannot route externally and denial adds no decision record; correction recovers.
- A saved decision remains visible after backend restart.
- Combined mode improves feasible utility over deterministic enterprise-only and Ruvnet-only baselines on the deterministic synthetic corpus.
- Ablations quantify loss from RuVector recall, Regorus policy, conformal calibration, and RVF durability.
